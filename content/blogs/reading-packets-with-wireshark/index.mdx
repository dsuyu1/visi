Most people meet networking through diagrams. This session was the other way around: start from a capture file and work back up to the model.

## Capture, then filter

Everyone started by capturing their own traffic for thirty seconds, which is long enough to produce far more packets than anyone wants to scroll. That is the point — the first real skill is filtering.

```text
http.request
ip.addr == 10.0.0.5 && tcp.port == 443
dns.qry.name contains "utrgv"
```

## Following a conversation

Follow TCP Stream did more for people's understanding than any slide. Watching a plaintext HTTP request and response line up in order makes the request/response model concrete, and it makes the case for TLS without anyone having to argue it.

## Where to practice

Public capture files are the cheapest way to keep going. Open one, pick a protocol you have never looked at, and figure out what the endpoints are saying to each other. Bring anything confusing to a meeting and we will work through it together.
